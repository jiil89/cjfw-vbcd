# 와이어프레임 — 회원가입 / 로그인 / Admin 승인 패널 / 웹 챗봇 UI

텍스트 기반 와이어프레임. 색상·폰트 등 비주얼 디자인은 다루지 않고, 화면의 레이아웃·구조·정보 배치만 정리한다.

- 회원가입/로그인/Admin 패널: 기존 목업이 없어 아래 문서에 실제로 언급된 필드/기능만 근거로 설계함
  - `docs/3-service-scenarios.md` (7번 시나리오)
  - `docs/4-prd.md` ("인증/보안" 절)
  - `docs/1-domain-definition-meeting-room-agent.md` (2번 온보딩 프로세스, 4번 핵심 엔티티)
- 웹 챗봇 UI: `docs/design/chatbot-shell.html`에 이미 있는 완성 레이아웃(상단바 / 채팅 스레드 / 하단 입력창+빠른명령칩 / 오른쪽 사이드바)을 그대로 텍스트로 옮긴 것 — 새로 디자인하지 않음

**[결정됨] 4개 화면 모두 반응형으로 만든다** (`docs/4-prd.md` 참고 — 사내 직원이 PC뿐 아니라 휴대폰으로도 접근). 기준 브레이크포인트는 `docs/design/chatbot-shell.html`에 이미 있던 값(860px)을 그대로 따른다: **860px 초과 = 데스크톱 레이아웃(위 와이어프레임 그대로), 860px 이하 = 아래 모바일 레이아웃.**

## 1. 회원가입 웹페이지

CJ 계정 정보 + 선호 회의실 + 앱 로그인 비밀번호를 함께 입력해 등록을 신청하는 화면. 로그인 전 공개 폼(anon 접근 가능).

```
┌───────────────────────────────────────────────┐
│  회의실 예약 — 계정 등록 신청                    │
├───────────────────────────────────────────────┤
│                                                 │
│  [ CJ WORLD 계정 ]                              │
│   CJ WORLD ID (email_alias)   [______________]  │
│   CJ WORLD PW                 [______________]  │
│   (CJ 자동화 로그인용으로 암호화 저장됨.          │
│    나중에 CJ WORLD PW를 바꾸면 앱에도 다시        │
│    등록해야 예약이 계속 됩니다)                   │
│                                                 │
│  [ 선호 회의실 (우선순위 순서) ]                  │
│   1순위  [ 회의실 선택 ▾ ]                       │
│   2순위  [ 회의실 선택 ▾ ]         [+ 추가]       │
│   3순위  [ 회의실 선택 ▾ ]         [- 삭제]       │
│   (선택 입력 — 비워둘 수 있음)                    │
│                                                 │
│  [ 이 앱 로그인 정보 ]                            │
│   앱 로그인 비밀번호           [______________]  │
│   앱 로그인 비밀번호 확인       [______________]  │
│   (CJ WORLD PW와 별개 값. 해시로 저장됨)          │
│                                                 │
│              [       등록 신청       ]           │
│                                                 │
│  이미 승인된 계정이 있으신가요? [로그인하러 가기]  │
│                                                 │
└───────────────────────────────────────────────┘

  ↓ 제출 후

┌───────────────────────────────────────────────┐
│  등록 신청이 접수되었습니다.                      │
│  승인되면 로그인하실 수 있어요.                   │
│  (화이트리스트 대상이면 자동 승인 /               │
│   아니면 관리자 승인 후 이용 가능)                 │
│                        [ 로그인 페이지로 이동 ]   │
└───────────────────────────────────────────────┘
```

- 요소
  - CJ WORLD ID / CJ WORLD PW 입력 필드 (도메인 정의서 User 엔티티: 사내 계정 식별자, 암호화된 CJ WORLD PW)
  - 선호 회의실 우선순위 입력 — 여러 개 추가/삭제 가능한 순서형 목록 (1순위부터)
  - 앱 로그인 비밀번호 + 확인 입력 필드 (CJ 비밀번호와 분리 저장됨을 안내하는 문구)
  - 제출 버튼 1개, 로그인 페이지로 가는 링크
  - 제출 후 접수 확인 안내 (자동승인/관리자승인 갈림을 안내하는 문구 포함), 비밀번호는 이 화면 어디에도 다시 노출하지 않음

**모바일 (≤860px)**

```
┌───────────────────┐
│ 회의실 예약 —      │
│ 계정 등록 신청      │
├───────────────────┤
│ CJ WORLD 계정       │
│ ID       [_______]│
│ 비밀번호  [_______]│
│                    │
│ 선호 회의실         │
│ 1순위 [선택 ▾]     │
│ 2순위 [선택 ▾]     │
│      [+ 추가]      │
│                    │
│ 이 앱 로그인 정보    │
│ 비밀번호  [_______]│
│ 확인     [_______]│
│                    │
│  [   등록 신청   ] │
│  [ 로그인하러 가기 ]│
└───────────────────┘
```

- 2컬럼(라벨+입력) → 1컬럼 전체폭으로 쌓임. 선호 회의실 [+ 추가]/[- 삭제] 버튼은 각 행 아래로 이동. 버튼은 터치하기 쉽게 전체폭.

## 2. 로그인 페이지

Admin 승인이 완료된 사용자가 앱 로그인 비밀번호로 로그인하는 화면. 웹 챗봇 UI / Admin 패널 공통으로 사용.

```
┌───────────────────────────────────────────────┐
│  회의실 예약 — 로그인                            │
├───────────────────────────────────────────────┤
│                                                 │
│   CJ WORLD ID           [______________]        │
│   앱 로그인 비밀번호       [______________] 표시  │
│                                                 │
│              [        로그인        ]           │
│                                                 │
│  아직 등록하지 않으셨나요? [회원가입 신청하러 가기] │
│                                                 │
├───────────────────────────────────────────────┤
│  상태 안내 영역 (조건별로 하나만 표시)             │
│   · 승인 대기 중: "관리자 승인을 기다리고          │
│     있어요. 승인되면 로그인하실 수 있습니다."       │
│   · 거부됨: "등록이 거부되었습니다."               │
│   · 비밀번호 불일치: "계정 ID 또는 비밀번호를       │
│     확인해주세요."                                │
│   · CJ 인증 실패: "CJ WORLD 계정 인증에 실패했어요.│
│     CJ WORLD PW를 바꾸셨다면 앱에도 다시 등록해야  │
│     합니다." → 아래 재등록 폼이 함께 열린다         │
├───────────────────────────────────────────────┤
│  [CJ_LOGIN_FAILED일 때만 노출] 재등록 폼          │
│   CJ WORLD PW를 바꾸셨나요?                      │
│   새 CJ WORLD PW      [______________]          │
│                        [    재등록    ]          │
└───────────────────────────────────────────────┘
```

- 요소
  - CJ WORLD ID + 앱 로그인 비밀번호 입력 필드, 로그인 버튼
  - 회원가입 페이지로 가는 링크
  - 로그인 시도 결과에 따른 상태 메시지 영역 (승인 대기/거부/자격증명 오류 — 온보딩 상태에 따라 분기)
  - 로그인 성공 시 JWT(access+refresh) 발급 후 웹 챗봇 UI(또는 Admin 권한이면 Admin 패널)로 이동
  - **[20260816 추가] CJ WORLD PW 재등록 폼** — `CJ_LOGIN_FAILED`일 때만 나타난다. 로그인은 CJ 세션 확보에 실패하면 거부되므로, CJ WORLD PW가 바뀐 사용자는 앱에 들어올 수 없고 앱 안의 재등록 화면(4번 사이드바)에 **도달할 수 없다** — 이 화면이 유일한 복구 지점이다. 본인 확인은 위에 이미 입력한 CJ WORLD ID + 앱 로그인 비밀번호로 하고, 새 CJ WORLD PW는 서버가 실제 CJ 로그인으로 검증한 뒤에만 저장한다(검증에 수 초 걸려 "CJ에서 확인 중…" 표시).
- **Tab 순서**: CJ WORLD ID → 앱 로그인 비밀번호 → "표시" 토글 순. "표시" 버튼은 화면상 라벨 우측에 있지만 DOM에서는 입력칸 뒤에 둔다(앞에 두면 ID 다음 Tab이 토글에 걸린다).

**모바일 (≤860px)**

원래도 폭이 좁은 단일 카드형 화면이라 데스크톱 레이아웃과 거의 동일 — 카드 폭만 화면 전체(여백만 남기고)로 늘어난다. 별도 재배치 없음.

## 3. Admin 승인 패널

대기 중인 등록 요청을 검토해 승인/거부하는 화면. 로그인 필요(Admin 권한 사용자만 접근).

```
┌───────────────────────────────────────────────────────┐
│  회의실 예약 — Admin 패널              [관리자명] [로그아웃]│
├───────────────────────────────────────────────────────┤
│  대기중인 등록 요청                                       │
│                                                         │
│  ┌─────────────────────────────────────────────────┐   │
│  │ CJ WORLD ID: hong.gd     신청일시: 08/13 09:10   │   │
│  │ 선호 회의실: 1순위 14F-2, 2순위 14F-3             │   │
│  │ 상태: 대기(Pending)                               │   │
│  │                        [ 승인 ]   [ 거부 ]        │   │
│  └─────────────────────────────────────────────────┘   │
│  ┌─────────────────────────────────────────────────┐   │
│  │ CJ WORLD ID: kim.js      신청일시: 08/13 08:50   │   │
│  │ 선호 회의실: (미입력)                             │   │
│  │ 상태: 대기(Pending)                               │   │
│  │                        [ 승인 ]   [ 거부 ]        │   │
│  └─────────────────────────────────────────────────┘   │
│                                                         │
│  (목록에 비밀번호/암호화된 값은 표시하지 않음)             │
│                                                         │
├───────────────────────────────────────────────────────┤
│  처리 완료 이력 (선택적으로 하단에 표시)                   │
│   · lee.mk — 승인 — 처리자: system(자동승인)             │
│   · park.sy — 거부 — 처리자: hong.gd                     │
└───────────────────────────────────────────────────────┘
```

- 요소
  - 상단: 관리자 식별 표시 + 로그아웃
  - 대기중인 등록 요청 목록 — 각 항목: CJ WORLD ID, 신청 일시, 선호 회의실(입력했다면), 상태, [승인]/[거부] 버튼
  - 비밀번호(CJ WORLD PW, 앱 로그인 비밀번호)는 어떤 형태로도 화면에 노출하지 않음
  - 처리 완료된 요청 이력(누가 언제 승인/거부했는지, 자동승인은 처리자 "system") — 참고용 하단 목록
  - 승인/거부 클릭 시 확인 후 처리, 처리 후 목록에서 제거되어 이력으로 이동

**모바일 (≤860px)**

```
┌─────────────────────┐
│ Admin 패널  [로그아웃]│ ← 관리자명은 아이콘/축약 표시
├─────────────────────┤
│ 대기중인 등록 요청     │
│ ┌─────────────────┐ │
│ │ hong.gd          │ │
│ │ 08/13 09:10      │ │
│ │ 선호: 14F-2,14F-3│ │
│ │ [ 승인 ] [ 거부 ] │ │
│ └─────────────────┘ │
│ ┌─────────────────┐ │
│ │ kim.js           │ │
│ │ 08/13 08:50      │ │
│ │ 선호: (미입력)    │ │
│ │ [ 승인 ] [ 거부 ] │ │
│ └─────────────────┘ │
│                      │
│ ▾ 처리 완료 이력      │ ← 기본 접힘(펼치기)
└─────────────────────┘
```

- 원래도 카드 목록이라 세로로 쌓는 구조는 동일. 카드가 화면 전체폭을 쓰고, 승인/거부 버튼은 카드 안에서 나란히(터치 타깃 확보). 처리 완료 이력은 화면을 많이 차지하니 기본 접어두고 펼쳐서 보게 한다(데스크톱은 항상 펼침).

## 4. 웹 챗봇 UI

`docs/design/chatbot-shell.html`의 레이아웃을 그대로 텍스트로 옮김. 로그인 세션 전제.

```
┌───────────────────────────────────────────────────────────────────┐
│ [회] 회의실 예약  상암S시티                      ● [정] 정지일       │ ← 상단바 (56px)
├───────────────────────────────────────────┬─────────────────────┤
│                                             │  오늘 예약           │
│  ── 오늘 · 8월 13일 목요일 ──                │  ┌─────────────┐    │
│                                             │  │ 데이터 아키텍처│    │
│  [A] 안녕하세요! 회의실 예약을 도와드릴게요.   │  │ 14F-2  14:00 │    │
│      날짜·시간·인원만 말씀해 주시면          │  │      –15:00  │    │
│      바로 확인해 드립니다.                   │  └─────────────┘    │
│                              오전 9:02       │                     │
│                                             │  선호 회의실          │
│                        내일 오후 2-3시에     │  [1] 14F-2   8인     │
│                        회의실 잡아줘 [정] →  │  [2] 14F-3   6인     │
│                              오전 9:03       │  [3] 3F-6   12인     │
│                                             │                     │
│  [A] 선호하시는 14F-2가 비어있어요.           │  ┌─────────────────┐│
│      이 조건으로 예약할까요?                 │  │같은 회의실은 하루  ││
│      ┌───────────────────────┐            │  │최대 2시간까지만    ││
│      │ 14F-2        14:00–15:00 │           │  │예약할 수 있어요.   ││
│      │ [예약가능][8인][선호1순위]│           │  │더 필요하면 다른    ││
│      │ [이 회의실로 확정][다른 곳]│           │  │회의실로 이어서     ││
│      └───────────────────────┘            │  │잡아드려요.        ││
│                              오전 9:03       │  └─────────────────┘│
│                                             │                     │
│                              응 좋아 [정] → │   (오른쪽 사이드바,   │
│                              오전 9:04       │    860px 이하 폭에서 │
│                                             │    숨김)             │
│  [A] 14F-2, 내일 14:00–15:00으로             │                     │
│      예약 완료했습니다.                       │                     │
│      ● 예약 확정                             │                     │
│                              오전 9:04       │                     │
│                                             │                     │
│                8명 이상 가능한 곳 있어? [정]→│                     │
│                              오전 9:07       │                     │
│                                             │                     │
│  [A] 15:00–16:00 기준, 8명 이상 가능한        │                     │
│      회의실이 3곳 있어요. 하나 골라주세요.     │                     │
│      [3F-6 12인] [15F-4 8인] [15F-5 8인]    │                     │
│                              오전 9:07       │                     │
│                                             │                     │
├─────────────────────────────────────────────┤                     │
│ [오늘 내 예약 조회] [자주 쓰는 회의실로 예약] [예약 취소]  ← 빠른명령칩│
│ ┌─────────────────────────────────────┐ ⊙   │                     │
│ │ 메시지를 입력하세요 (예: 내일...)      │(보내기)│                     │
│ └─────────────────────────────────────┘     │                     │
└───────────────────────────────────────────┴─────────────────────┘
```

- 전체 구조: 상단바(56px 고정) + 본문(좌: 채팅 컬럼 1fr / 우: 사이드바 300px, 2컬럼 그리드)
- 상단바: 좌측 브랜드(로고+서비스명+"상암S시티"), 우측 사용자 칩(온라인 상태 점 + 아바타 + 이름)
- 채팅 컬럼(좌, 1fr auto 세로 그리드)
  - 채팅 스레드 영역(스크롤): 날짜 구분선("오늘 · 8월 13일 목요일") → Agent/사용자 메시지가 좌/우로 번갈아 배치, 각 메시지에 타임스탬프
  - Agent 메시지 안에 들어갈 수 있는 인터랙션 카드 2종
    - 단일 회의실 제안 카드: 회의실명 + 시간, 태그(예약가능/인원/선호순위), [이 회의실로 확정]/[다른 곳 보기] 버튼
    - 다중 회의실 선택 그리드(3열): 회의실명 + 인원 태그, 클릭해서 선택
  - 예약 확정 후 "● 예약 확정" 상태 라벨
  - 하단 입력창(composer): 빠른명령 칩 행(오늘 내 예약 조회 / 자주 쓰는 회의실로 예약 / 예약 취소) + 텍스트 입력 필드 + 원형 보내기 버튼
- 오른쪽 사이드바(rail, 폭 300px, 860px 이하 화면에서 숨김)
  - "오늘 예약" — 오늘 확정된 예약 카드(회의명, 회의실, 시간)
  - "선호 회의실" — 우선순위 번호 + 회의실명 + 수용인원, 1순위 강조
  - **[20260816 추가] "비밀번호"** — 접힌 항목 2개. 두 비밀번호는 성격이 완전히 다르므로(하나는 CJ 시스템 인증용, 하나는 이 앱 로그인용) 한 폼에 섞지 않고 각각 펼쳐서 입력받는다.
    - `CJ WORLD PW 재등록` — "CJ WORLD에서 비밀번호를 바꾸셨다면 여기에도 다시 등록해야 예약이 계속 됩니다" 안내 + 새 PW 입력. 서버가 실제 CJ 로그인으로 검증한 뒤에만 저장하므로 수 초 걸린다("CJ에서 확인 중…").
    - `앱 로그인 비밀번호 변경` — 현재 PW + 새 PW(8자 이상). 성공 시 기존 세션(refresh 토큰)이 모두 끊긴다.
  - 규칙 안내 박스 — "같은 회의실은 하루 최대 2시간까지만 예약할 수 있어요" 같은 정책 고정 안내문
- 이 사이드바 내용은 **데스크톱 사이드바와 모바일 하단 시트가 같은 컴포넌트를 공유**한다(`ChatRailContent`) — 한 곳만 고치면 양쪽에 반영된다.
