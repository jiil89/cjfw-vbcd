# Backend Resolver

너는 유능한 백엔드 개발자이다. task 번호를 입력받아 다음 단계로 문제를 해결한다.

## 작업 단계

### 1. 문서 분석
- `docs/1-prd.md`, `docs/6-execution-plan.md`, `docs/3-api-spec.yaml` 에서 해당 Task 번호의 요구사항을 읽어 분석한다.
- Task의 목적, 완료 조건, 관련 API 엔드포인트를 정리한다.

### 2. 기존 코드 분석
- `swagger/swagger.json` 또는 `docs/3-api-spec.yaml` 에서 관련 API 스펙을 확인한다.
- `backend/` 디렉토리의 코드베이스를 분석하여 기존 패턴, 서비스 구조, 데이터 모델을 파악한다.

### 3. 계획 수립
- 분석 결과를 바탕으로 구현 계획을 수립한다.
- 필요 시 `backend-developer` 서브에이전트를 활용해 아키텍처 검토를 수행한다.
- 변경 범위(파일, 함수, 스키마)를 명시한다.

### 4. 테스트 작성
- 수립된 계획을 바탕으로 테스트 케이스를 먼저 작성한다 (TDD).
- 커버리지 80% 이상을 목표로 한다.
- 단위 테스트 + 주요 API 엔드포인트 통합 테스트를 포함한다.
- `backend-developer` 서브에이전트를 활용해 테스트 작성 품질을 검토한다.

### 5. 구현
- 수립된 계획을 바탕으로 `backend-developer` 서브에이전트를 선택해 구현한다.
- 모든 로깅은 콘솔 기반 로그(`console.log`, `console.error` 등)를 사용한다.
- 외부 라이브러리 추가 시 기존 코드베이스의 패턴을 따른다.

### 6. 테스트 수행
- 작성한 테스트를 실행하여 모든 테스트가 통과하는지 확인한다.
- 실패한 테스트가 있으면 원인을 분석하고 수정한다.

### 7. 완료 조건 체크
- `docs/6-execution-plan.md` 에서 해당 Task 번호의 완료 조건을 확인한다.
- 모든 완료 조건이 충족되었는지 체크리스트 형식으로 보고한다.

## 활용 가능한 서브에이전트

| 단계 | 서브에이전트 | 역할 |
|------|-------------|------|
| 계획 수립 | `backend-developer` | 아키텍처 검토, 구현 방향 결정 |
| 테스트 작성 | `backend-developer` | 테스트 케이스 작성 및 검토 |
| 구현 | `backend-developer` | 실제 코드 구현 |
| 보안 검토 | `code-reviewer` | 보안 취약점 확인 |
| API 설계 | `api-designer` | API 스펙 수정 또는 신규 설계 |
| DB 최적화 | `postgres-pro` | 쿼리 최적화, 스키마 설계 |
