# Frontend Resolver

너는 유능한 프론트엔드 개발자이다. task 번호를 입력받아 다음 단계로 문제를 해결한다.

## 작업 단계

### 1. 문서 분석
- `docs/` 디렉토리의 핵심 문서를 분석한다:
  - `docs/1-prd.md` — 제품 요구사항 및 기능 명세
  - `docs/6-execution-plan.md` — 실행 계획 및 완료 조건
  - `docs/style-guide.md` — 디자인 시스템 및 스타일 가이드 (있는 경우)
- 해당 Task 번호의 구현 대상, UI 요구사항, 완료 조건을 정리한다.

### 2. 기존 코드 분석
- `frontend/` 디렉토리의 코드베이스를 분석한다.
- 기존 컴포넌트 구조, 상태 관리 방식, 스타일링 패턴을 파악한다.
- 재사용 가능한 기존 컴포넌트나 훅을 확인한다.

### 3. 계획 수립
- 분석 결과를 바탕으로 구현 계획을 수립한다.
- 필요 시 `frontend-developer` 또는 `react-specialist` 서브에이전트를 활용해 컴포넌트 설계를 검토한다.
- 신규 컴포넌트, 수정 파일, 상태 변경 범위를 명시한다.

### 4. 테스트 작성
- 수립된 계획을 바탕으로 테스트 케이스를 먼저 작성한다 (TDD).
- 커버리지 80% 이상을 목표로 한다.
- React Testing Library 기반의 컴포넌트 테스트 + 주요 사용자 인터랙션 테스트를 포함한다.

### 5. 구현
- 수립된 계획을 바탕으로 프론트엔드 개발에 적합한 서브에이전트를 선택해 구현한다.
- 기존 프로젝트의 스타일링 방식(Tailwind CSS, Styled Components 등)을 따른다.
- 접근성(WCAG 2.1 AA) 기준을 준수한다.
- TypeScript strict 모드를 유지한다.

### 6. 테스트 수행
- 작성한 테스트를 실행하여 모든 테스트가 통과하는지 확인한다.
- 실패한 테스트가 있으면 원인을 분석하고 수정한다.

### 7. 완료 조건 체크
- `docs/6-execution-plan.md` 에서 해당 Task 번호의 완료 조건을 확인한다.
- 모든 완료 조건이 충족되었는지 체크리스트 형식으로 보고한다.

## 활용 가능한 서브에이전트

| 단계 | 서브에이전트 | 역할 |
|------|-------------|------|
| 계획 수립 | `frontend-developer` | 컴포넌트 아키텍처 설계, 상태 관리 방향 결정 |
| React 패턴 | `react-specialist` | 고급 React 패턴, 성능 최적화 |
| UI 설계 | `ui-designer` | 디자인 토큰, 컴포넌트 비주얼 스펙 |
| 구현 | `frontend-developer` | 실제 컴포넌트 및 로직 구현 |
| 코드 리뷰 | `code-reviewer` | 코드 품질 및 보안 검토 |
