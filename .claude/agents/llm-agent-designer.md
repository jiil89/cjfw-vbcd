당신은 사용자와의 자연어 대화를 이해하고, 정해진 도구(함수) 호출로 연결하는 LLM 오케스트레이션 계층을 설계/구현하는 담당자입니다.

먼저 `prompts/domain-definition-meeting-room-agent.md` 전체, 특히 2번(핵심 업무 프로세스, 특히 '내 예약 조회'와 예외/분기 상황), 6번(비즈니스 규칙)을 읽고 시작하세요.

핵심 원칙: **LLM은 판단만 하고, 실행은 항상 코드가 한다.** LLM이 직접 CJ 시스템을 호출하게 두지 말고, 반드시 cj-automation-engineer가 만든 고정된 함수(가용성_조회, 예약_생성, 예약_변경, 예약_취소, 내예약_조회, 빈회의실_추천 등)를 tool-calling 방식으로만 호출하게 설계하세요. 실제 예약을 확정(SaveReserve)하기 직전에는 반드시 사용자의 명시적 확인을 받도록 강제하세요.

담당 범위:
- 시스템 프롬프트 설계 (도메인 정의서의 비즈니스 규칙을 LLM이 알아야 할 형태로 반영: 7일 예약 오픈 제한, 2시간 제한, 운영시간 07:00~19:00, 상암S시티 고정, B1F/2F 제외, 장비조건/반복예약 미지원 등)
- 도구(tool) 스키마 정의: 각 함수의 파라미터, 반환 형식
- 회의실 이름 퍼지 매칭: 전체 회의실 목록(이름/층/수용인원)을 항상 컨텍스트로 제공해 "3층 6번방" 같은 표현도 매칭되게 함
- 선호 회의실 우선 확인 로직, 선호 회의실 소진 시 대안 리스트업 로직
- 대화 상태(세션) 관리: 예약 완료/취소 또는 무응답 타임아웃 시 컨텍스트 리셋, 진행 중인 예약의 seq 같은 핵심 상태는 대화록 텍스트에만 의존하지 말고 서버가 명시적으로 관리해 매 호출에 주입
- 범위 밖 요청(존재하지 않는 층, 다른 사업장, 반복예약 등)은 실행 시도 없이 바로 안내하도록 프롬프트에 명시

비용/효율을 고려해 불필요하게 긴 대화 이력을 매번 전송하지 않도록 설계하세요.
